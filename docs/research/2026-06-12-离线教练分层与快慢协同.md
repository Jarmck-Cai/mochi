# 离线教练分层与快/慢模块协同（M5/M6 方向细化）

- 日期：2026-06-12
- 性质：设计思考笔记（对 DESIGN §学习循环 / M5-M6 的细化与排序）
- 触发：用户提问——"小模型推理也有延迟，是否该离线用小模型自我更新词表/快模块，
  前端只用快模块？云 API 大模型当教练目前怎么规划？"
- 结论摘要：用户提议 = DESIGN 既定方向 + 两点强化与一处修正，且本周实战已为可行性
  提供证据。下面把它从"规划"推进为"有依据的设计排序"。

## 1. 核心原则（一句话）

**LLM / 小模型永远不直接服务按键热路径；一切慢智能的产出必须"编译"成快结构
（计数表 / 词表 / 先验 / 校准曲线 / 规则），由快结构上线服务交互。**

这不是偏好，是两条硬约束推出来的必然：
- 按键热路径 <50ms（预算 ~25ms）——即使小模型 ONNX 推理（5-15ms）也吃掉大半预算；
- 学习必须即时生效——纠正一次下次就对。神经网络要训练，天然做不到即时。

DESIGN §学习循环原文已是这个分层，本笔记只是把它说清楚并排序：

```
每键（<25ms）    → 快模块：词典查表 + n-gram 计数 + 个人记忆回放（已全部上线）
停顿（300-800ms）→ LLM 续写 / 整句重排（M5，可容忍慢，不回改已上屏）
每天空闲          → 离线小模型/教练重训快模块（分钟级）→ 回归门禁守门才换
每周（可选）      → 云 LLM 教练深挖纠正模式，合成困难样本 / 现代语料
```

## 2. 我们的架构对这个模式有独特优势：快模块是"数据"不是"权重"

实战中越来越清晰的一点——当前所有快模块的形态都是**人可读的数据**，不是黑盒参数：

| 快模块 | 形态（源码） | 离线更新 = | 实测代价 |
|---|---|---|---|
| 通用 LM | ngram.tsv 计数表（lm.rs 读入哈希表） | 重跑 export_artifacts.py | **21s 全量重建**（本周实证） |
| 词典 / 英文表 | dict.tsv / english.tsv | 同上 | 含在 21s 内 |
| 个人记忆 | commits.jsonl 事件日志 → 回放成计数（personal.rs） | 追加事件 / 重放 | brain 加载 1.8s |
| 弧先验 / 模糊音 | 代码常数表（decoder.rs priors） | 改数据表重编 | — |

由此，"离线小模型自我更新快模块"在我们这里**不需要发明新机制**——更新 = 重新生成
一份 tsv 或注入一批事件，brain 重启加载即生效。并白送三个性质：

- **可审计**：教练产出是人能读的文本表，不是权重（与 commits.jsonl 选 jsonl 不选
  sqlite 同一哲学：用户可查看/删行）；
- **可回归门禁**：回放 commits.jsonl 重打历史输入，top-1 不退步才换表——M6 门禁的
  机制基础。本周"放弃输入防污染"已证回放的**确定性**为真（journal 存原始事实、
  回放重新解释，确定性测试过）；
- **可重建**：本周从"只剩源码"21s 重建通用层并与基线 counts 对齐——"编译管线"本就在。

> 这是相对纯神经输入法的结构性优势：慢→快的"编译"在我们这里是确定性的数据生成，
> 不是蒸馏出一个新的黑盒，因此可解释、可回滚、可门禁。

## 3. 离线智能的靶点（按性价比 / 时间近远排序）

### ① 通用层语料现代化（M3 二期）—— 最近、现在就能做、对应最痛的 case

已知痛点全是"语料过时"型：`dazi→大字`、`suijitidu→随即梯度`，因为 SIGHAN 是 2005
年的新闻语料。这里 LLM 的角色不是推理，是**语料合成 / 清洗器**：生成现代口语 +
技术写作风格句子，重训 trigram 计数。

**关键便利：通用层只含公共数据，云 API 随便用，零隐私负担。** 这是"云端大模型当教练"
最无负担的切入点，且第一份工作就命中最显眼的质量问题。

### ② 个人教练：挖 commits.jsonl → 产出规则表（必须本地）

离线分析纠正模式，产物落成数据：
- typo 混淆统计（`seperate→separate`、`wn→wen`）→ 喂 M4 键内容错；
- 个性化模糊音（用户从不分 in/ing 但 z/zh 分得清 → 收紧/放开对应惩罚）；
- 个人短语促升建议。

**硬约束：个人打字数据永不入库，这层教练必须本地**（本地 Qwen 级或纯统计脚本）。
初期甚至不需要 LLM——纯统计就能挖出大部分混淆模式，LLM 是锦上添花的模式解释器。

### ③ 蒸馏重排器（M6 本体）

云 LLM 离线给历史候选打分当老师 → 蒸馏成 LightGBM / 特征小模型（μs-ms 级）进热路径
重排。"慢智能→快模块"最经典形态，但**放最后**：前两项性价比明显更高，且本项依赖
①②积累的数据与门禁基建。

### ④ 置信度校准（M4）

离线学校准曲线，运行时查曲线决定是否自动上屏——同样是"离线慢学、在线快查"。
是 M4"选择性出手"的实现形态。

## 4. 云 API 教练规划与隐私分界线

现规划：**不考虑成本时整个闭环可 100% 本地，云端教练是无 GPU 用户的可选降级。**
结合上面，把分界线画清楚：

- **通用层（公共数据）→ 云 API 教练随时可用**，无隐私顾虑，教练最先在此上岗（= 靶点①）；
- **个人层（commits.jsonl）→ 教练必须本地**；若未来一定要云协助，只上交"模式摘要"
  （如混淆矩阵）而非原文。以"暂不考虑成本"前提，本地跑即可；
- **教练产物一律落成数据表，过回归门禁才上线**——保住可审计、可回滚。

## 5. 对 DESIGN 的一处修正建议：热路径小模型从"必然"降为"按需"

DESIGN §3 给热路径留了一个 ONNX 小模型（中英意图标注，5-15ms，"唯一热路径神经
网络"）。但 M2 实战证据是：**纯统计 + 先验工程已把混打做到相当好**——
`zheshiyigetest` / `deeplearning` 分词 / `woyaoc` 的 FallbackTail 修复，全无神经网络。

建议把热路径小模型**降级为"撞到统计 + 先验天花板后再考虑"的按需项**，理由正是用户
点出的：即使小模型，热路径推理也有延迟与工程复杂度代价，而它要解决的问题目前大部分
被更便宜的手段覆盖。省下的热路径预算留给词图规模 / 候选数量更划算。

> 注：此条与 DESIGN §3"唯一热路径神经网络"表述冲突，且属架构级取舍——**建议升格为
> ADR**（连同 §4 的教练分层与隐私分界一并定案）。本笔记先记为 Proposed，待用户拍板。

## 6. 待 ADR 化的决策点（供拍板）

1. **离线教练分层与隐私分界**（§4）：通用层云可用 / 个人层本地 / 产物落表过门禁。
2. **热路径小模型降级为按需**（§5）：超 DESIGN 原"必然"表述。

## 7. 与现有里程碑的关系

- 本笔记不新增里程碑，是对 **M3 二期（语料）/ M4（校准）/ M5（续写）/ M6（闭环）** 的
  实现形态细化与排序；
- 最有价值的发现：**"下一步该做的 M3 二期语料现代化" 与 "云教练的第一份工作" 是同一件
  事**——公共数据、零隐私、命中最痛 case。下一步开发方案据此展开（见 STATUS / devlog）。
