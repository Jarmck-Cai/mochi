# 实验 001 流水线验证报告（草稿）

- 日期：2026-06-10
- 状态：**流水线验证完成；正式实验等待真实个人语料**
- ⚠️ 重要声明：本报告所有数值基于**替身个人语料**（《动手学深度学习》中文版章节）。
  替身语料只用于证明"流水线能端到端运行、指标能测出个人层收益"，**数值不构成对项目
  假设（README 通过标准 ≥10pp）的最终结论**。真实结论以用户本人语料重跑后为准。

## 一、目的

在拿到用户真实历史文本之前，把"拼音键流 → 词图 → 解码 → 指标"的离线评测链路完整跑通，确认：

1. 整条链路在 Windows / 纯 Python 下端到端可运行（不依赖 kenlm）；
2. 评测指标能区分"纯通用 LM"与"通用 LM + 个人层"；
3. 个人层（个人 n-gram + 个人词库）在术语密集语料上能测出正向收益；
4. 通用领域对照集上个人层不造成明显回退。

## 二、流水线构成

```
run_experiment.py          一键端到端：数据 → LM → 词图 → 解码 → 指标对比表
pipeline/
  prepare_data.py          下载开源资源（rime 词典 / SIGHAN 语料 / 英文词表 / d2l 章节）
  corpus.py                语料清洗（markdown 去噪）、子句切分、按文档时间序切 train/test
  pinyinize.py             汉字 → 无调拼音键流（pypinyin，多音字按词消歧；中英混排保留英文）
  lattice.py               词图：拼音字弧 + 拼音词弧 + 英文词弧（通用/个人）+ 兜底字母弧
  lm.py                    纯 Python trigram + stupid backoff（加权计数 = 时间衰减）
  personal.py              个人层：个人 trigram（文档级 0.95^age 衰减）+ 个人词库
                           + 英文大小写习惯（resnet→ResNet）+ 评测用术语表（仅从 train 提取）
  decoder.py               beam search；打分 = log(μg·P通用 + μp·P个人)
                           + λ·个人词库奖励 + 弧类型先验
  evaluate.py              整句首选命中率 / 字级准确率 / 术语命中率 / 中英段命中率
```

与 DESIGN.md 第三节打分公式的对应：λ₁/λ₂ 两项 LM 以概率空间线性插值实现；λ₃ 场景先验
本实验恒为 0（离线无前台应用信号）；λ₄ 上下文衔接未实现（子句独立解码）。

## 三、数据

| 用途 | 来源 | 规模 |
|---|---|---|
| 拼音词典 | rime 明月拼音 `pinyin_simp.dict.yaml` | 65,121 字/词条目 |
| 通用 LM 语料 | SIGHAN Bakeoff 2005 PKU+MSR 分词语料 | 467,932 句 / 279 万词 |
| 通用英文词表 | google-10000-english | 1 万词 |
| 替身个人语料 | 《动手学深度学习》中文版 36 章（GitHub d2l-zh） | ~748KB markdown |
| 通用对照集 | PKU 语料尾部 held-out（不参与任何训练） | 200 子句 |

替身语料按章节课程顺序当作"时间序"：前 29 章训练个人层（6,806 子句，个人词库 668 词，
其中词典外中文词 646 个），后 7 章（Adam、fine-tuning、word2vec、BERT 等）抽 800 个测试
子句（含 74 个中英混排）。测试章节的主题词训练集中未必出现，与真实场景"新话题"一致。

## 四、实验组设置

| 配置 | 通用 LM | 个人 LM | 个人词库 |
|---|---|---|---|
| baseline(generalLM) | μ=1.0 | — | — |
| +personalLexicon | μ=1.0 | — | λ=0.8 |
| +personalLM | μ=0.65 | μ=0.35 | — |
| full(+LM+lexicon) | μ=0.65 | μ=0.35 | λ=0.8 |

消融即上表中间两行（README 方法第 5 条；场景先验无数据，未消融）。
beam=12，所有配置共用同一词图构建器（baseline 不含个人词弧）。

## 五、结果（2026-06-10 实际运行输出）

运行环境：Windows 11 / Python 3.11 / 纯 CPU；通用 LM 训练 23s；解码 20-35 ms/子句。

### 个人领域测试集（替身语料，800 子句）

| config | items | 整句首选命中率 | 字级准确率 | 术语命中率 | 中英段整句命中 | 英文词召回 |
|---|---|---|---|---|---|---|
| baseline(generalLM) | 800 | 46.9% | 83.9% | 81.8% | 2.7% | 50.0% |
| +personalLexicon | 800 | 49.9% | 86.1% | 89.1% | 10.8% | 56.2% |
| +personalLM | 800 | 63.2% | 90.4% | 98.8% | 18.9% | 57.5% |
| full(+LM+lexicon) | 800 | **63.6%** | **90.7%** | **99.4%** | **18.9%** | **57.5%** |

### 通用领域对照集（人民日报 held-out，200 子句）

| config | items | 整句首选命中率 | 字级准确率 |
|---|---|---|---|
| baseline(generalLM) | 200 | 32.0% | 76.8% |
| +personalLexicon | 200 | 31.0% | 76.8% |
| +personalLM | 200 | 31.5% | 76.5% |
| full(+LM+lexicon) | 200 | 31.0% | 76.5% |

逐句对比：full 对 baseline **143 赢 / 9 输**（其余持平）。

### 解读（仅就流水线有效性而言）

- 个人层带来整句首选 **+16.7pp**、术语命中 **+17.6pp**——指标方向和幅度均符合"链路能测出
  个性化收益"的验证目标；消融显示个人 LM 贡献大于个人词库，二者叠加最优。
- 通用对照集回退在 1pp 以内 → 个人层未明显伤害通用输入。
- 赢例多为领域表达（"随机梯度下降"不再被解成"岁集体都下降"、"学习率"不再是"学习绿"）；
  9 个败例多为轻度过个性化（如"实践中"被个人高频词"时间"压过、"的/地"混淆），
  正式实验时可通过调小 μp 或对低频上下文降权缓解。
- 中英混排段绝对值低（18.9%）：测试章节引入的新英文术语（bert、word2vec 等）训练集没见过，
  个人词库无从学起——这正是真实产品里"第一次输入新术语仍然难"的真实写照，
  也是 LLM 新术语挖掘（DESIGN 第四节）要解决的问题。

## 六、已知局限

1. **替身语料偏书面、重复度高**（教材文风统一），个人 LM 收益可能被高估；真实聊天/笔记
   语料噪声更大。数值不可外推。
2. **键流是从目标文本反推的**（pypinyin），多音字按 pypinyin 词典消歧，与用户真实击键
   存在偏差（约 1-2% 子句目标因此不可达，对所有配置同等影响）；未模拟模糊音、缩写
   （如 'zgrm'）、打错键。
3. **通用 LM 偏弱**：279 万词新闻语料的 trigram，对照集整句命中仅 32%，距商业输入法基线
   有差距。基线越弱个人层收益越显大，正式实验前应扩大通用语料（计划中的 KenLM 大语料
   在产品阶段解决）。
4. **打分公式简化**：场景先验 λ₃、上下文衔接 λ₄ 未实现；λ 权重为手设（μp=0.35, λlex=0.8），
   未做网格搜索。
5. **评测口径**：子句独立解码（无跨句上下文）；术语表从 train 集自动提取（145 条），
   口径偏保守；英文大小写按个人习惯还原，统计时大小写敏感。
6. **解码速度**（20-35ms/子句，纯 Python）只用于离线评测，与产品热路径预算无关。

## 七、真实语料到位后的操作

1. 把 .txt/.md 个人历史文本按时间顺序命名，放入 `data/personal/`（格式详见 `data/README.md`）；
2. 重跑 `.\.venv\Scripts\python.exe run_experiment.py`；
3. 对照 README 通过标准（术语密集场景整句首选 ≥10pp）读 `results/metrics.json`，
   把结论写入 `report.md` 并回写 STATUS.md / ROADMAP。
