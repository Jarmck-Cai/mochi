用户想在本机装试用版没装成。排查发现机器被剥到只剩源码（gitignore 的重产物全失），

## 起点：装不上，为什么

用户右键 install.ps1 装不成。逐环排查后真相：

1. **release/windows/ 只有三个脚本，从没打过 payload**（bin/weasel/artifacts/rime-config
   都不在），install.ps1 一跑就找不到文件。package-windows.ps1 也没成功跑过。
2. **更深**：打包要收集的重产物，磁盘上大半不在了——它们全被 gitignore（"track via
   scripts, not git"）：
   - LM artifacts `dict/ngram/english.tsv` + 训练语料（SIGHAN）+ `.venv` —— 全无
   - fork weasel 三件套（WeaselServer.exe/weasel.dll/weaselx64.dll）—— 全无
   - 在的只有：brain.exe（今日新构建）、fork rime.dll（翻译器插件，核心）、rime-config
3. **推断**：用户按 README 第 1 步重装了官方 Weasel 0.17.4 → 覆盖了之前部署的 fork
   （证据：Program Files 无 .stock 备份，rime.dll 是原版 3524096 字节 ≠ fork 2874880）
   → 然后 install.ps1 因无 payload 失败。机器 = 干净官方 Weasel + Mochi 没装。

## 决策（问用户）

- **Weasel 端**：fork 三件套已丢，重建是 C++ 编译。用户选**先用官方版 + fork rime.dll**
  ——少"候选内灰字 ghost"视觉，其余全功能。最快能打字。

## 做了什么

### 1. 通用层 artifacts 从零重建（experiments/001-personalization-gain）

- `py -m venv .venv`；`pip install wordfreq opencc pyyaml pypinyin`（pypinyin 第一次跑
  才暴露缺）
- `python -m pipeline.prepare_data` 幂等下载公共数据：rime pinyin_simp 词典、SIGHAN
  icwb2-data（**sighan.cs.uchicago.edu 老链接仍活**）、英文表、D2L 替身语料
- essay.txt（八股文）**从官方 Weasel 安装目录拷**：`C:\Program Files\Rime\weasel-0.17.4\
  data\essay.txt`（6.3MB）→ data/dict/essay.txt
- `python export_artifacts.py` → 21s 产出 artifacts/v0/{dict,ngram,english}.tsv +
  meta.json。**counts 与提交基线对齐**：dict 372717 / ngram 453539/955754/235688 /
  english 47947 / essay_words 373565（仅 +1 漂移，37 万分之一，忠实复现）
- brain 自检：1818ms 加载，counts 全对，监听 \\.\pipe\mochi-brain-v0 ✓

### 2. 部署：官方 Weasel + fork rime.dll，仿真新用户布局

目标布局照搬好友版 install.ps1：`%LOCALAPPDATA%\Mochi\{bin,artifacts\v0,user_data}`
+ rime-config 进 `%APPDATA%\Rime` + brain 开机自启（HKCU Run / vbs 隐藏窗口）。
唯一差别：**只换 rime.dll，不动官方 Weasel 三件套**。

### 3. 标准用户提权坑（本 session 最大的"为什么"）

`Jarmck` 是**标准用户（非管理员）**。最初写了个自提权 deploy-local.ps1 做全部事——
但**标准用户 UAC 提权会切到管理员账户身份**，那样脚本里的 `%LOCALAPPDATA%`/`%APPDATA%`/
`HKCU` 全指向管理员 profile，per-user 数据就装错位（brain 自启进管理员 hive、输入方案
进管理员 Rime 而 Weasel 以 Jarmck 跑读不到）。原版 install.ps1 也有这个潜在 bug——
它默认好友本人是管理员（同用户提权 profile 不变），对标准用户机器不成立。

**修法——按权限边界拆分**：
- per-user 部分（Mochi 目录、artifacts、rime-config、HKCU 自启、启 brain、
  WeaselDeployer /deploy、启 server）**全部以 Jarmck 身份做**（主会话非提权 shell 直接做）
- **只"停 server + 换 rime.dll"用最小化提权脚本 swap-rimedll.ps1**——只碰 Program Files，
  不碰任何 per-user 路径，完成标记写死到 Jarmck 的 %TEMP% 供回读
- server 用 `Start-Process WeaselServer.exe`（Jarmck 身份）起回中完整性——顺带消除了
  devlog 记过的"提权 server 继承高完整性"隐患

提权两次被取消（标准用户 UAC 是凭据框，非简单点是），第三次用户输入管理员凭据通过。

## 经验沉淀

- **gitignore 的重产物 = 一旦本地清掉就得重建**：本 session 证明 artifacts 21s 可重建
  （脚本齐全、公共数据链接还活、essay 能从官方 Weasel 借）。但 **fork weasel 三件套
  无任何备份、重建要 C++ 工具链**——这是真正的脆弱点。建议归档 fork 构建产物到固定
  非 git 位置。
- **"装官方覆盖即全失"**：用户重装官方 Weasel 把 fork 直接抹了且无 .stock。供应链脆弱。
- **标准用户机器的部署 ≠ 管理员机器**：提权切 profile 是隐蔽陷阱。原则——per-user 操作
  绝不放进提权块；提权块只做真正系统级（Program Files / 停提权进程）的最小动作。
- **逐环取证再次奏效**：六处依赖逐个 ls/find/stat/size 比对，不靠猜就定位了"机器被剥空"。
