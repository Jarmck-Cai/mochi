# 2026-06-12（五）— ghost 灰字"还是看不到"：高亮态配色才是凶手

## 用户反馈

局部候选 ✅（混在完整候选里可用，体验提升）；灰色 ghost 仍不可见，
preedit 仍是 ‥ 分割（后者是阶段 0 设计行为，不是 bug）。

## 排查过程（逐环验证，全部排除后剩下的就是答案）

按"brain → 插件 → weasel 解析 → 绘制 → 配色"逐环取证：

1. **部署面**：fork 三件套 + rime.dll 时间戳全对，运行中的 WeaselServer
   就是 fork（Program Files 唯一一份）
2. **数据面**：console 解码 `shangxiaw` → `上下文` comment=`▸文`，候选以
   ghost 结尾，满足解析条件；插件确认传递 comment（mochi_translator.cc:116）
3. **编译面**：fork 源文件带 UTF-8 BOM（`L'▸'` 编译正确）；escape_string
   只转义 \\ \n \t；补丁源码时间早于 x64 产物时间（Win32 链接失败不影响，
   部署的是 x64）
4. **配色面（命中）**：`WeaselPanel.cpp:862-869`——高亮候选的 ghost 用
   `hilited_comment_text_color`，我们配的 0xeeeeee；而 aqua 高亮候选是
   **蓝底白字（0xffffff）**，两者肉眼不可分。**补全候选几乎总是首选=
   高亮候选**，所以用户盯着看的地方永远"没有灰"。非首选候选的 0x999999
   灰其实一直在工作，只是用户的注意力不在那里

## 修复（纯配置，无需重编/UAC）

- weasel.custom.yaml：`hilited_comment_text_color` 0xeeeeee → **0x80ffffff**
  （AABBGGRR 半透明白；fork 的 _TextOutGhost 取 alpha 通道，蓝底上渲染为
  褪色浅蓝白——正是 Copilot ghost 的视觉感）
- WeaselDeployer /deploy 重编 + server 重启（已验证 build/weasel.yaml 带新值）

## 顺手修的两个部署隐患

- **server 一直提权运行**：deploy-weasel.ps1 在提权上下文 Start-Process
  重启 server → server 继承高完整性级别（进程路径都读不出来，后续普通
  权限无法重启它）。改用 `explorer.exe` 间接启动，落回桌面用户级别。
  本次已手工以普通权限重启（pid 19696）
- deploy 脚本补分发 weasel.custom.yaml（之前只靠手工拷贝）

## 经验沉淀

- **"在高亮行上的灰色"是独立的设计决策**：dimmed 样式必须针对每种背景
  分别选色，高亮背景上的"灰"≠ 普通背景上的灰。半透明白是对任意深色
  背景都成立的通解
- 逐环取证胜过猜测：六个环节五个排除，剩下的就是根因——而且每一环的
  验证手段（时间戳、console 解码、BOM 检查、源码 grep）都不需要看屏幕
- 提权脚本里启动的常驻进程会继承提权——部署脚本启动用户态服务一律
  经 explorer.exe 间接启动
