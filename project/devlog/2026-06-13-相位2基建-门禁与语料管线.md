## 怎么走到这的（讨论链）

1. **用户问"系统底层是查表还是 LLM"** → 澄清：当前是**经典统计**——词典查表(候选) +
   trigram n-gram(stupid backoff，lm.rs) + 个人记忆**事件溯源计数**(personal.rs，
   commits.jsonl 回放+按天衰减 0.98+纠正 3x)。**热路径无任何神经网络**。LLM/小模型是
   M5 规划、未实现。即时学习 = 计数 +1，不是训练——这是 LLM 做不到的。

2. **用户问"小模型离线自更新词表/快模块？云教练怎么规划"** → 形成设计共识，落
   docs/research/2026-06-12-离线教练分层与快慢协同.md：
   - **核心原则**：LLM/小模型永不直接服务按键；慢智能产出必须"编译"成快结构
     （计数表/词表/先验/曲线），由快结构上线。
   - **本架构优势**：快模块是**数据不是权重**，所以慢→快是确定性数据生成，可审计/
     可回归门禁/可重建（本周实证 artifacts 21s 重建）。
   - **四靶点排序**：①通用层语料现代化（云可用零隐私，命中最痛）②个人教练挖
     commits.jsonl（必须本地，先纯统计）③蒸馏重排器（M6）④置信度校准（M4）。
   - **隐私分界**：通用层云可用 / 个人层必须本地 / 产物落表过门禁。
   - **对 DESIGN 的修正**（标 Proposed 待 ADR）：热路径小模型从"必然"降为"撞到统计
     天花板再上"——M2 实战证明纯统计+先验已把混打做得很好。

3. **相位制开发方案**（STATUS 下一步）：关键发现——两个主开发靶点都**需要真实 miss
   清单**才能精准命中，故分相位：相位0固本 / 相位1用+攒数据 / 相位2主开发。
   避免"凭印象开训=优化猜测"。

## 做了什么（按 commit）

- **相位 0 固本**（c52808f 一部分 + 仓库外）：① fork rime.dll+brain.exe+ghost patch
  备份到**仓库外** E:\Projects\mochi-binbackup（防 git 操作/官方覆盖误伤；weasel 三件套
  已丢无副本，README 记重建配方）；② brain 自启**模拟开机**验证通过（杀进程→跑注册
  命令→自动回来）；③ 失误速记通道 project/misfire-log.md。

- **回归门禁 gate.py**（d806b05）：相位 2 安全锁。重训后全自动裁决——对照集(公共 PKU
  held-out 200 句，冻结成 gate/control.tsv)不退 + 目标集(过时词 gate/target.tsv)提升，
  才 exit 0。**全自动无人工**（用户明确要求，否则违背"教练自动更新"初衷）；逐条翻转写
  报告只作调试。复用 make_eval_item/PKU held-out 方法论/brain --decode --no-user-data。
  - 端到端验证：old==new→target FAIL exit1；essay λ=1 vs λ=0→抓 4 条真实对照回退
    （净+1 掩盖个别 lost，报告兜底——印证讨论时的隐患）。
  - **副产发现**：建门禁时实测 suijitidu 已被 essay 底座治好（随即→随机），剩"补全过冲
    多补下降"属 [补全] 噪声非语料过时——从 target 降级、记 misfire-log。

- **重训管线**（48e8823）：export_artifacts.py 加 --extra-corpus/--extra-weight，把现代
  语料（同 SIGHAN 分词格式）注入 trigram（SIGHAN 体量大故支持加权）。闭环实证：8 句 demo
  现代语料 weight=50 → dazi「大字→打字」(候选本就排第二)、control 零损伤 → 门禁 PASS exit0。

- **本地小模型 vs 云 API 讨论**：用户问"先不建云、先本地小模型？"。机器有 RTX A2000/6GB
  （能跑 Qwen 3-4B）。结论：**(a) 相位 2 语料用现成公共语料、零模型**最实用且贴合架构；
  本地小模型留给"个人教练/生成"那个**既需模型又强制本地**的位置最值；云 API 暂不建。

- **真实语料管线 + 首次实证**（b2b9666）：build_modern_corpus.py（Leipzig zho_news
  CC BY → **pkuseg** 分词）。**选 pkuseg 而非 jieba**：基座是 SIGHAN PKU+MSR，pkuseg 按
  PKU 标准（失配 3.5% vs jieba 9.8%），避免计数被两种切法劈开。
  - 实测 10K 新闻 weight=1：**control 70→69%（回退 2 句文学句）、dazi 未修（新闻无"打字"）
    → 门禁正确 exit 1 拦下**。
  - **三条结论**：① 管线端到端可用；② **语域(register)是第一要素**，新闻修不动口语词
    还伤文学句；③ 门禁兑现价值（拦下没门禁就会悄悄变差的改动）。二阶问题：控制集是 PKU
    （偏文学），"打字输入法是否该为诗句优化"值得复审控制集语域构成（留待）。

- **风险固化**：fork weasel 三件套无任何副本，重建要 C++ 工具链——已备份能备的、记重建

- **方法论锁定**：相位 2 继续往下 = 数据驱动。无真实 miss 时继续灌语料只会被门禁拦
  （已用证据验证），所以**停在基建完成处是对的**。
